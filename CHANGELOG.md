# Changelog

All notable changes to Atlas Realm are recorded here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) · Versioning: [SemVer](https://semver.org/) with milestone tags (`v0.1.0-m0`, `v0.2.0-m1`, …).

## [Unreleased]

### Added
- Placement rules (M2-1, #66): the rules that decide where a building may stand now exist and are tested. A building must sit fully inside the map, must not cover a reserved area or another building, and may only be turned in quarter turns. "Find a spot" (auto-place) picks the nearest free plot, always the same one for the same map, and says so when the map is full. A building's saved position is the north corner of its footprint, and turning a building keeps it in place (ADR-0024). Nothing on screen uses this yet; the placement tool and commands come later in M2, and both will use these same rules so the preview and the real result can't disagree.
- Storage for buildings and the hotbar (M2-2, #67): the database (schema v5) can now remember where each project's building stands on the map and what each of the ten hotbar slots points to. The database itself makes sure a project has at most one building, a slot holds one thing, the same project isn't pinned twice, and a building or pin can only point at a project in the same world. Removing a building or clearing a slot never changes or deletes the project (ADR-0023). Existing databases are backed up and upgraded automatically, and all existing projects start without a building. Nothing on screen uses this yet; placing buildings and pinning shortcuts come later in M2.
- Placement commands (M2-3, #68): the app can now place, move, turn and remove a project's building, and list every building in a world. The trusted main process checks every request again with the same rules as the preview, so a building can't overlap another one or hang off the map. A refusal says why and which buildings are in the way (ADR-0025). The building's size always comes from the app's own art list, never from the request. Removing a building never changes the project: it keeps its name, ID and files and simply has no building. Archiving or trashing a project now also removes its building, in one step; restoring leaves it without one. An archived project can be placed again, and the list says it is archived so the map can show it differently. Every new building uses the placeholder 2×2 art for now. Nothing on screen uses these commands yet; the world view (M2-6) and the placement tool (M2-7) come next.
- New main screen layout (M2-5, #70): the screen now has a sidebar with entrances (Projects, Agents Guild, Skill Library, Tool Shops, Automations, Activity, Settings), a world area in the middle, the Realm Atlas and an inspector on the right, and a bottom bar with the Library button and the hotbar. Your project list opens straight away, as before. Features that aren't built yet say so ("Not built yet (planned for M3+)") instead of showing made-up content. Press `E` to open or close the library (a placeholder for now). Press Escape to close the open panel; you're returned to the button you came from. Shortcuts never fire while you type in a text field or while a confirmation is open. In narrow windows, the Atlas and inspector move into a drawer.
- Hotbar commands (M2-4, #69): the app can now pin a project or a sidebar service (Agents Guild, Skill Library, Tool Shops, Automations, Activity, Settings) to one of a world's ten hotbar slots, unpin it, and list the pins. A filled slot is never overwritten by accident: the app answers "that slot holds something else" and says what is in it, and only replaces it when the request names that exact item. The same check stops an old screen from unpinning the wrong thing (ADR-0026). Unpinning never changes the project. An archived or trashed project keeps its pin and is shown with its status; a project in the trash can't be newly pinned, an archived one can. Creating an eleventh project never pushes a pin out. Nothing on screen uses these commands yet; the hotbar bar comes later in M2.
- The world shows your buildings (M2-6, #71): the middle of the main screen now draws the world with every building saved for it, using placeholder art (and says so). Click a building to see its project in the Inspector; double-click it or press "Open" to see the project's details. Clicking the ground clears the selection, and the view never jumps. An archived project's building looks faded with an "Archived" sign, and the Inspector offers "Unarchive". Projects without a building are marked "Not placed" in the Projects list and work as before. Buildings outside the view are skipped when drawing, so the world stays smooth with 100 buildings.
- Place, move and remove buildings (M2-7, #72): choose “Place on map” on a project (in the Projects list or the Inspector) and a preview follows your pointer. It shows in blue with “Fits here” where the building can stand, and in red with the reason (“another building is in the way”, “off the map”) where it can’t. Click to place it. To move a building, choose “Move building” in the Inspector and drag it; dropping it somewhere it can’t stand leaves it where it was. “Remove from map” asks first and tells you the project, its files and its runs are kept: it just shows as “Not placed”. “Auto-place” puts the building on the nearest free spot in one click, even without the map, and tells you when the world is full. Everything works from the keyboard too: arrow keys move the preview, “Place here” saves it, and Escape cancels without changing anything.
- Undo and redo for buildings (M2-8, #73): the Undo and Redo buttons above the map (or Ctrl+Z, and Ctrl+Y / Ctrl+Shift+Z) take back placing, moving or removing a building, and do it again. The buttons say what they will undo. Only building changes are undone: never a project, a file or a run. If the building changed elsewhere in the meantime, or its old spot is taken now, undo says so, skips that step and changes nothing. The keys do nothing while you type in a text field. The list starts empty when you switch world or profile, or restart.

- Comfort settings (M2-14, #79): each building on the map now shows its project's name on a label that stays readable at any zoom (labels hide when you zoom far out to an overview). Turn labels off with the "Labels" checkbox above the map or in Settings. The world now remembers where you left the camera in each world and opens there next time, kept on the map. Settings has a new Comfort section: motion can follow the Windows "reduce animations" setting (the default) or be forced on or off. Atlas Realm has no animations yet, so this changes nothing you can see today; it is ready for later. These choices are saved in your profile and never get in the way of saving your avatar or name.
- The library (M2-9, #74): press `E` or "Library [E]" to open it. Its Projects tab is your full project list, with a new "On map" filter (All / Placed / Not placed) that works together with Active / Archived / Trash and search, so you can find, say, archived projects that have no building. Every project now has an "Open" button too, so you can open, rename, archive, trash, restore, place and remove from the map without touching the world. The Agents, Skills, Tools and Workflows tabs say "Planned for M3". Building Appearances shows the building art that comes with the app, marked as placeholder art. Use the arrow keys to move between tabs. A new "Hide world view" button in the top bar hides the map until you show it again or restart; everything else keeps working.
- Project links (M2-11, #76): the app can now store links between two projects of the same world: "depends on", "supports" or "references". Each link is an arrow, so "A supports B" and "B supports A" are different links. A link is a note about how projects relate: it never changes permissions, schedules or files, and removing a link never touches either project. A project can't be linked to itself, the same link can't be made twice, and a project in the trash can't be linked (an archived one can). Links of a project in the trash are hidden and come back when you restore it. A world can hold up to 5000 links. The app can also list a world's projects (including ones without a building) and their links, at most 150 projects and 300 links at a time, and says how many were left out. Existing databases are backed up and upgraded automatically (schema v6). Nothing on screen uses this yet; the Atlas Connections tab comes later in M2.
- The Realm Atlas (M2-12, #77): the upper-right panel is real now. Its Map tab shows your world from above: the map's edges, every building, the selected building and a dashed box for what the world view is showing. Click a building on the Map (or in its Buildings list) to select it; the camera stays put. Press "Go to" to bring the camera to it, or switch on "Follow selection" to have the camera follow what you select (never while you are placing or moving a building). You can collapse the Atlas, expand it, drag or arrow-key its left edge to resize it, and pin it to a project ("Pinned to: …"). These choices are remembered for each world. In narrow windows the Atlas & inspector drawer now sits beside the world instead of over it, so it never hides the map's controls (ADR-0031). The Connections tab says "Not built yet"; it comes next. The old mock Atlas is only under Developer spikes.
- Realm Atlas Connections (M2-13, #78): the Atlas's Connections tab now shows how your projects are linked. Every project of the world appears, including ones without a building (rounded, "no building", in the middle) and archived ones (dashed border). Arrows point from one project to the other, and each kind of link has its own label and line: "depends on" is solid, "supports" dashed, "references" dotted. A legend explains this, and when a world has more than 150 projects the tab says how many it left out. Add a link with the "Add a link" form; remove one from the Links list, after a confirmation that says only the link goes and both projects stay exactly as they were. The Links list shows each link's source, relation, target and who made it, and works fully from the keyboard. Clicking a project in the graph or the list selects it in the world and on the Map too, and never starts any work. You can drag projects around the graph to tidy it up; that never moves a building, and "Reset layout" puts them back (positions are forgotten when you restart; ADR-0032). With reduced motion on, the graph doesn't animate.

### Changed
- The Realm Atlas graph library, React Flow, is now version 13 (Dependabot PR #55, ADR-0030), along with eight smaller tool updates. Nothing changes on screen: the developer-spike graph selects and highlights projects as before. Two small code changes kept it working with the new version.

### Fixed
- The world-view test for hover, zoom and pan no longer fails at random (#71): it now reads where the camera really is instead of assuming it.
- Projects in an archived world can no longer be changed (#59): renaming, editing the goal, archiving, restoring, trashing and restoring from the trash are all refused with "This world is archived. Restore it before changing its projects.", and nothing is changed. You can still open and list those projects. There is no button to archive a world yet, so this is a safety rule for later screens rather than something you will see today.

### Security
- Faster refusal of bad requests (#56): the app now refuses binary data, unusual objects and oversized requests from its own window before checking them in detail. Before, one 10 MB binary message could keep the trusted main process busy for several seconds. The 64 KiB limit is unchanged, but it now applies to the request as sent: padding that would be trimmed away still counts.

## [0.2.0-m1] - 2026-11-20 — M1: Profiles, worlds, and project persistence

### Added
- Local profiles on disk (M1-2, #29): the app now keeps a small profile list, `profiles-index.json`, and opens the last-used profile's own database at startup. Existing M0 data is kept and becomes the profile "Default"; a brand-new install creates "Default" with a random ID (ADR-0017). The list is saved so that a crash can never leave it half-written. If it is damaged, missing while profile data exists, or from a newer app version, the app explains this and closes without changing or deleting anything. Profile folder names are only ever built from checked IDs, so an edited list can't point the app outside its data folder. There is no profile picker or switching yet; those come later in M1.
- Project storage (M1-3, #30): the local database now has tables for profile settings, worlds and projects (schema v2), with rules the database enforces itself: tidy, length-limited names, a fixed list of project statuses, and every project belonging to exactly one world. A project keeps the same ID when renamed. Archiving and trashing never delete anything, and restoring from the trash puts a project back where it was (ADR-0016). Every change checks that nobody else changed the record in the meantime, so edits can't silently overwrite each other. Existing databases are backed up and upgraded automatically. Nothing in the UI uses this yet; project commands and screens come next in M1.
- Project templates (M1-5, #32): the app ships two starter templates, **Generic** and **Content Campaign**, each with its own input fields, planned outputs and offline limitations. They are metadata only for now: no workflows or agents until M3/M4, and each template says so. The app checks every template at startup. A broken one is listed as unavailable with a reason, and the app still starts. Developers can list them through the new `template.list` query. They don't show up in the UI yet (that comes with the project list, M1-10).
- Graph entity IDs (M1-4, #31): every world and project now gets a permanent graph ID of its own (schema v3), separate from its name and from where it is drawn, so the Realm Atlas and imports can link to it later. It is saved together with the world or project, or not at all. Trashing a project marks its graph entry as removed without deleting it, and restoring brings back the same ID. Existing databases are backed up and upgraded, and existing worlds and projects get their IDs during the upgrade (ADR-0018). Database writes that must happen together can no longer be half-saved after a disk-full or I/O error. Nothing in the UI uses this yet.
- Profile and world commands (M1-6, #33): the interface can now list and create profiles, rename the open profile, read and change its settings (avatar and timezone), and create, list and rename worlds. Every command is checked in the trusted main process and works only on the profile that is open. A world from another profile can't be seen or changed. Setting up an avatar is optional: every profile starts with no avatar and your computer's timezone. When something can't be done, the app now says why with a clear reason, for example "changed since it was loaded, reload and try again", instead of a generic error (ADR-0019). Creating a profile doesn't switch to it yet (switching comes in M1-8), and only one world theme ("meadow") and one avatar exist so far. There are no screens for this yet (M1-9).

- Project commands (M1-7, #34): the interface can now create a project in a world from a bundled template (Generic or Content Campaign), open it by ID, list a world's active, archived or trashed projects 50 at a time, rename it, change its goal, archive and restore it, and move it to the trash and back. A project keeps its ID through renames and restarts. Archive and trash never delete anything. A project from another world or profile can't be seen or changed, and edits based on an old copy are refused instead of overwriting newer changes. Run handling for archive and trash is a labelled placeholder until runs exist (M4). A world holds up to 1000 projects. The database upgrades itself to schema v4 so it accepts the real template IDs (`builtin.generic`); before this, no project could be created from a bundled template (ADR-0020). There are no screens for this yet (M1-10).
- Profile switching (M1-8, #35): the interface can now switch to another profile. The app first opens the other profile's data. Only when that works does it stop the background worker, close the current profile, start a fresh worker and reload the window, so nothing from the old profile stays on screen or in memory. If the other profile can't be opened (missing, damaged or from a newer app version), the app says so and stays on the current profile, with nothing changed or deleted (ADR-0021). Requests sent during the switch are refused with a clear "switching profiles" answer instead of running against the wrong profile. Worker requests that were still running are stopped and never repeated. The app remembers the chosen profile next time it starts. There is no switch button yet (M1-9/M1-10).
- First-launch screens (M1-9, #36): the app now opens on a short, offline first launch instead of the developer test page. Pick or rename your local profile (no account or internet needed), optionally give your placeholder avatar one of six colours (or skip it), and create your first world. You then land on your world's home, which says plainly that it has no projects yet. Settings lets you change or remove the avatar, create, rename and switch profiles, and rename the world later. Switching opens the other profile's own worlds and settings. Creating projects is shown but not available yet (M1-10). The old M0 test panels moved into a collapsed "Developer spikes" section, still labelled as mock data. Everything works by keyboard (ADR-0022).
- Project list (M1-10, #37): your world's home now lists its projects, with Active, Archived and Trash filters, a search over names and goals, and a "Load more" button for long lists. **New project** lets you pick a template (Generic or Content Campaign), with its real description, the fields it will ask for later, its planned outputs and its offline limits, then give a name and an optional goal. You can rename a project, edit its goal, archive and restore it, and move it to the trash and back. Each of those asks first and says plainly what happens and what does not: nothing is deleted and no files are moved. Because no AI runs exist yet, it also says there is nothing to stop, rather than claiming it checked. If a project was changed somewhere else in the meantime, the list reloads and tells you so. Every project appears in the list whether or not it has a building. Everything works by keyboard and with screen readers.
- M1 acceptance tests (M1-11, #38): every M1 Check now has an end-to-end test on both the dev build and the packaged app. A project is created and reopened offline across a restart, a rename keeps its identity, profiles stay separate and a switch replaces the background worker, and archive and trash leave a file outside the profile folder untouched. The packaged smoke test now goes through the real first launch.

### Security
- Chromium switch guard (M1-1, #20): the installed app now refuses to start when it is launched with switches that would let another program take over its trusted window, such as `--remote-debugging-port`, `--no-sandbox` or `--disable-web-security` (29 switches in all, ADR-0015). It exits before it opens the database or a window. `pnpm dev` is unaffected. Packaged smoke tests use a separate test-only build that allows only the debugging port and is never shipped.

## [0.1.0-m0] - 2026-11-10 — M0: Foundation and risk spikes

### Added
- Background worker spike (M0-6, #9): the app now starts a separate **worker process** (an Electron utility process, ADR-0012) for long-running trusted work, so the window never freezes while it runs. Requests carry IDs, are checked on both sides and have a size limit, and they can be cancelled while running. If the worker crashes, the app reports it, fails the waiting requests instead of hanging (without retrying them), and starts a fresh worker on the next request. A "Worker check (M0 spike)" panel shows the worker's real state and runs an echo plus a cancelled slow count. It does no product work yet.
- Art contract and placeholder art (M0-8, #11): the art bible's technical values are now fixed (ADR-0013): 64 × 32 tiles, 2×2/3×3/4×4 building footprints, a ground pivot on the footprint's south corner, and a 16-colour "warm storybook village" palette. Four clearly flagged **placeholder** sprites (ground tile, 2×2 building, selection and invalid markers) are generated by code, so no PixelLab account is needed. They are listed in `resources/assets/asset-manifest.json` with a checked schema. The world's selection highlight is now drawn from its PNG and uses the palette colours, and the art ships inside the app and works offline.
- Realm Atlas spike (M0-5, #8): a Realm Atlas panel in the upper-right corner with a Connections graph drawn by React Flow (ADR-0003). It shows **mock** entities, and each one is also a marker in the world. Selecting a node highlights the same entity in the world, and clicking a marker selects the same node in the graph, because both views read one shared selection. A keyboard-usable list view is included. A "Load stress graph (150 / 300)" spike button checks performance: it loads in under 0.2 s and stays smooth. Nothing is saved, and the Map tab comes later.
- Placeholder world view (M0-4, #7): the window now shows a 64 × 64 isometric grid drawn with PixiJS (WebGL, falling back to Canvas2D). Hover a tile to see its grid position, zoom with the wheel or the Zoom buttons, and pan with the middle mouse button. If graphics can't start or the GPU context is lost, the world area shows a message and the rest of the app keeps working. The grid is an M0 placeholder: no projects or buildings yet, and nothing in the view is saved. ADR-0011.
- Windows packaging (M0-7, #10): `pnpm package` produces an unsigned NSIS installer (per-user, no admin) and an unpacked app. The packaged app is hardened with Electron fuses: no run-as-Node, no `NODE_OPTIONS` or `--inspect` code injection, and a modified app archive refuses to start. `file:` requests are blocked everywhere. The window now shows the launch count stored in the local database (an M0 sample). A packaged smoke test runs the real `.exe` from a folder with spaces and non-ASCII characters, both locally and in CI. Uninstalling keeps your data. Uses Electron's default icon for now.
- Safer UI loading (M0-9, #16): the built app now loads its interface from its own `app://atlas` origin instead of `file://`. The page can no longer load scripts or images from local files or network shares (closing a Windows login-hash leak route), and IPC commands are accepted only from that origin.
- Local database (M0-3, #6): the app keeps a SQLite database in its user-data folder (built-in `node:sqlite`, ADR-0010). It has versioned migrations that run in transactions, an automatic backup before upgrading an existing database, and a clear error (no silent reset) if the database can't be opened. For now it stores only launch facts. Only one copy of the app can run at a time.
- Electron app shell (M0-2, #5): a window titled "Atlas Realm" with a sandboxed, isolated renderer, a strict CSP, and blocked navigation and pop-ups. A single Zod-validated IPC command (`app.ping`, an M0 spike) round-trips from the UI to the main process. Covered by unit tests and Playwright E2E tests. Build tooling: electron-vite (ADR-0009).
- Developer tooling (M0-1, #4): pnpm via corepack, strict TypeScript, ESLint + Prettier, Vitest, and CI running all checks on Windows. No runnable app yet.

- Project setup: split product spec into focused docs, AI-assisted development process, Claude Code configuration (CLAUDE.md, skills, subagents, hooks, MCP), GitHub workflow (CI, templates, labels, milestones).
