# Changelog

All notable changes to Atlas Realm are recorded here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) · Versioning: [SemVer](https://semver.org/) with milestone tags (`v0.1.0-m0`, `v0.2.0-m1`, …).

## [Unreleased]

### Added
- Local profiles on disk (M1-2, #29): the app now keeps a small profile list, `profiles-index.json`, and opens the last-used profile's own database at startup. Existing M0 data is kept and becomes the profile "Default"; a brand-new install creates "Default" with a random ID (ADR-0017). The list is saved so that a crash can never leave it half-written. If it is damaged, missing while profile data exists, or from a newer app version, the app explains this and closes without changing or deleting anything. Profile folder names are only ever built from checked IDs, so an edited list can't point the app outside its data folder. There is no profile picker or switching yet; those come later in M1.
- Project storage (M1-3, #30): the local database now has tables for profile settings, worlds and projects (schema v2), with rules the database enforces itself: tidy, length-limited names, a fixed list of project statuses, and every project belonging to exactly one world. A project keeps the same ID when renamed. Archiving and trashing never delete anything, and restoring from the trash puts a project back where it was (ADR-0016). Every change checks that nobody else changed the record in the meantime, so edits can't silently overwrite each other. Existing databases are backed up and upgraded automatically. Nothing in the UI uses this yet; project commands and screens come next in M1.
- Project templates (M1-5, #32): the app ships two starter templates, **Generic** and **Content Campaign**, each with its own input fields, planned outputs and offline limitations. They are metadata only for now: no workflows or agents until M3/M4, and each template says so. The app checks every template at startup. A broken one is listed as unavailable with a reason, and the app still starts. Developers can list them through the new `template.list` query. They don't show up in the UI yet (that comes with the project list, M1-10).
- Graph entity IDs (M1-4, #31): every world and project now gets a permanent graph ID of its own (schema v3), separate from its name and from where it is drawn, so the Realm Atlas and imports can link to it later. It is saved together with the world or project, or not at all. Trashing a project marks its graph entry as removed without deleting it, and restoring brings back the same ID. Existing databases are backed up and upgraded, and existing worlds and projects get their IDs during the upgrade (ADR-0018). Database writes that must happen together can no longer be half-saved after a disk-full or I/O error. Nothing in the UI uses this yet.
- Profile and world commands (M1-6, #33): the interface can now list and create profiles, rename the open profile, read and change its settings (avatar and timezone), and create, list and rename worlds. Every command is checked in the trusted main process and works only on the profile that is open. A world from another profile can't be seen or changed. Setting up an avatar is optional: every profile starts with no avatar and your computer's timezone. When something can't be done, the app now says why with a clear reason, for example "changed since it was loaded, reload and try again", instead of a generic error (ADR-0019). Creating a profile doesn't switch to it yet (switching comes in M1-8), and only one world theme ("meadow") and one avatar exist so far. There are no screens for this yet (M1-9).

### Security
- Chromium switch guard (M1-1, #20): the installed app now refuses to start when it is launched with switches that would let another program take over its trusted window, such as `--remote-debugging-port`, `--no-sandbox` or `--disable-web-security` (29 switches in all, ADR-0015). It exits before it opens the database or a window. `pnpm dev` is unaffected. Packaged smoke tests use a separate test-only build that allows only the debugging port and is never shipped.

## [0.1.0-m0] - 2026-11-10 — M0: Foundation and risk spikes

### Added
- Background worker spike (M0-6, #9): the app now starts a separate **worker process** (an Electron utility process, ADR-0012) for long-running trusted work, so the window never freezes while it runs. Requests carry IDs, are checked on both sides and have a size limit, and they can be cancelled while running. If the worker crashes, the app reports it, fails the waiting requests instead of hanging (without retrying them), and starts a fresh worker on the next request. A "Worker check (M0 spike)" panel shows the worker's real state and runs an echo plus a cancelled slow count. It does no product work yet.
- Art contract and placeholder art (M0-8, #11): the art bible's technical values are now fixed (ADR-0013): 64 × 32 tiles, 2×2/3×3/4×4 building footprints, a ground pivot on the footprint's south corner, and a 16-colour "warm storybook village" palette. Four clearly flagged **placeholder** sprites (ground tile, 2×2 building, selection and invalid markers) are generated by code, so no PixelLab account is needed. They are listed in `resources/assets/asset-manifest.json` with a checked schema. The world's selection highlight is now drawn from its PNG and uses the palette colours, and the art ships inside the app and works offline.
- Realm Atlas spike (M0-5, #8): a Realm Atlas panel in the upper-right corner with a Connections graph drawn by React Flow (ADR-0003). It shows **mock** entities, and each one is also a marker in the world. Selecting a node highlights the same entity in the world, and clicking a marker selects the same node in the graph, because both views read one shared selection. A keyboard-usable list view is included. A "Load stress graph (150 / 300)" spike button checks performance: it loads in under 0.2 s and stays smooth. Nothing is saved, and the Map tab comes later.
- Placeholder world view (M0-4, #7): the window now shows a 64 × 64 isometric grid drawn with PixiJS (WebGL, falling back to Canvas2D). Hover a tile to see its grid position, zoom with the wheel or the Zoom buttons, and pan with the middle mouse button. If graphics can't start or the GPU context is lost, the world area shows a message and the rest of the app keeps working. The grid is an M0 placeholder: no projects or buildings yet, and nothing in the view is saved. ADR-0011.
- Windows packaging (M0-7, #10): `pnpm package` produces an unsigned NSIS installer (per-user, no admin) and an unpacked app. The packaged app is hardened with Electron fuses: no run-as-Node, no `NODE_OPTIONS` or `--inspect` code injection, and a modified app archive refuses to start. `file:` requests are blocked everywhere. The window now shows the launch count stored in the local database (an M0 sample). A packaged smoke test runs the real `.exe` from a folder with spaces and non-ASCII characters, both locally and in CI. Uninstalling keeps your data. Uses Electron's default icon for now.
- Safer UI loading (M0-9, #16): the built app now loads its interface from its own `app://atlas` origin instead of `file://`. The page can no longer load scripts or images from local files or network shares (closing a Windows login-hash leak route), and IPC commands are accepted only from that origin.
- Local database (M0-3, #6): the app keeps a SQLite database in its user-data folder (built-in `node:sqlite`, ADR-0010). It has versioned migrations that run in transactions, an automatic backup before upgrading an existing database, and a clear error (no silent reset) if the database can't be opened. For now it stores only launch facts. Only one copy of the app can run at a time.
- Electron app shell (M0-2, #5): a window titled "Atlas Realm" with a sandboxed, isolated renderer, a strict CSP, and blocked navigation and pop-ups. A single Zod-validated IPC command (`app.ping`, an M0 spike) round-trips from the UI to the main process. Covered by unit tests and Playwright E2E tests. Build tooling: electron-vite (ADR-0009).
- Developer tooling (M0-1, #4): pnpm via corepack, strict TypeScript, ESLint + Prettier, Vitest, and CI running all checks on Windows. No runnable app yet.

- Project setup: split product spec into focused docs, AI-assisted development process, Claude Code configuration (CLAUDE.md, skills, subagents, hooks, MCP), GitHub workflow (CI, templates, labels, milestones).
