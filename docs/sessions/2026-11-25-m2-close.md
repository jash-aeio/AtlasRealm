## Retrospective
**Went well**
- Scope held at twice M1's size: 21 planned issues, 21 delivered in 5 days, and every M1 follow-up became a tracked issue that landed (except #61, gated to M3).
- Four parallel lanes plus an integrator worked. Every Check is proven by a UI test and by forged commands, and on the packaged `.exe`.
- Pure shared rules (placement rules M2-1) meant the preview and the trusted handler can't disagree. The same idea is worth repeating for permissions in M3.

**Didn't go well**
- Two lanes shared one checkout on 2026-11-22 and a commit landed on the wrong branch.
- Status docs on `main` kept saying "in review" after merges (#57–#62, #77, #78, #80), so every next task started by fixing them.
- A new rare flake (#108) appeared just as the old ones were fixed.

**Change next time**
- Create the worktree in `/start-task` for any parallel lane, never later.
- Write "merged" status updates as part of the next task's first commit (or `/sync-pm` right after a merge), so `main` docs are never stale for long.
- Fix #108 in the first M3 slice, so a red E2E run means a real problem again.
