## What was done
- **Migration 2** (`src/main/storage/migrations/index.ts`):
  - Every table is STRICT and has `created_at`, `updated_at` and `revision`.
  - CHECKs require trimmed names of 1–80 characters, slug IDs, a semver template version, `#rrggbb` avatar colours, and preferences that are a JSON object of at most 16 KiB.
  - Profile IDs must be `default` or a UUID (ADR-0014).
  - `projects.world_id` is a foreign key with `ON DELETE RESTRICT`.
  - A table CHECK keeps status and timestamps consistent.
  - Index `projects_by_world_status`, which a test shows the query planner really uses.
- **Repositories** (`src/main/storage/repositories/`):
  - `repository-support.ts` holds `RepositoryError` with stable codes (`not_found`, `already_exists`, `invalid_input`, `revision_conflict`, `invalid_transition`), the `LIMITS`, input checks and `guardedUpdate`.
  - `ProfileSettingsRepository`, `WorldRepository`, `ProjectRepository`.
  - `ProjectRepository` has no delete method, and a test checks that.
- **Validation found during testing:** `Intl` accepts `+02:00` as a time zone, which isn't an IANA ID. The timezone check now also requires an IANA-shaped name (starting with a letter; `Etc/GMT+2` still passes).
- **Existing tests updated for schema v2:** `tests/e2e/storage.spec.ts`, `tests/e2e-packaged/packaged.spec.ts` (one line each) and `tests/integration/app-launch-info.test.ts`, which now uses `MIGRATIONS.length`, so M1-4 won't need to touch it.
- `database.ts` re-exports `SQLInputValue`, so it stays the only module that imports `node:sqlite`.

- **invariant-reviewer:** no violations; all acceptance criteria confirmed.
- **security-auditor:** approve, with 7 Low findings and no Critical/High/Medium. All 7 are fixed in this PR, because migration 2 is still unreleased and can change for free:
  - **L1/L2:** preferences must be plain JSON data, at most 32 levels deep.
  - **L3:** names and goals refuse invisible spoofing characters, and names refuse line separators.
  - **L4:** unpaired surrogates are refused.
  - **L5:** timezones are stored in canonical spelling.
  - **L6:** the migration's CHECKs are tighter: exact UUID shape, no NUL, IANA-shaped timezone.
  - **L7:** the settings insert is race-free.
- One thing I caught myself: my first fix for L2 compared a JSON round trip, which would not have caught `Date` or `Map` (both stringify the same way twice). I replaced it with a walk that accepts only plain JSON types.
