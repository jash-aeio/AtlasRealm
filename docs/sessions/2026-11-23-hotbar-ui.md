# 2026-11-23 — Ten-slot hotbar UI (M2-10 #75)

## Task

Issue #75: replace the ten placeholder hotbar slots in the bottom bar with a working hotbar.
Pin projects (and services) to slots 1–9, 0, activate them with the number keys, and never
replace a slot without asking (§22.2 #2). Branch `feat/75-hotbar-ui`.

Definition of Ready: acceptance criteria present; depends on #69 and #74, both closed; no
`needs-decision` label.

## Plan (proposed)

1. **Hotbar store** `src/renderer/hotbar/hotbar.ts` (pure TypeScript, like `world-placements.ts`):
   reads `hotbar.list`, looks up pinned project names with `project.get`, and wraps
   `assign` / `clear` into plain outcomes (`ok`, `occupied` with the occupant, `error`).
   Unit tests in `tests/domain/hotbar-store.test.ts`.
2. **Hotbar bar** `src/renderer/hotbar/Hotbar.tsx`: ten slots labelled with their key and name.
   Empty slots say "Empty"; archived or trashed projects say so in text. Clicking a slot or
   pressing its key (through the shortcut layer, ignored in text fields) selects the project or
   opens the service panel. Each filled slot has an Unpin button; unpinning reports that the
   project itself is not affected.
3. **Pin dialog** `src/renderer/hotbar/PinDialog.tsx`: "Pin to hotbar" opens a list of the ten
   slots with what each holds. An empty slot pins straight away; an occupied one shows a
   confirmation naming the current shortcut (Replace / Cancel). The same confirmation appears
   if the main process answers `slot_occupied` because the slot filled up meanwhile.
4. **Wiring**: a `onPin` prop on `ProjectItem` (list and library) and the inspector, plus a pin
   button in the service entrance panels; `MainScreen` owns one hotbar store per world.
5. **E2E** `tests/e2e/hotbar.spec.ts`: §22.2 #2 through the UI (ten slots filled, an eleventh
   project, restart, everything still there), replace confirmation, unpin message, number keys.

## Decisions so far

- User (AskUserQuestion): plan approved; services are pinned with a "Pin to hotbar" button in
  each service panel's header (all six, including the "not built yet" ones).
- Routine: names of pinned projects come from `project.get` per pin (at most ten small reads),
  so no contract change is needed.
- Routine: a target that is already pinned shows "On hotbar (slot N)"; its dialog offers
  Unpin instead of a slot list. Moving a pin is unpin, then pin (no `hotbar.move` needed yet).
- Routine: unpinning from the bar needs no confirmation (it only removes a shortcut and is
  easy to redo); the message says the project is not affected.
- Routine: a trashed project's row hides "Pin to hotbar" unless it is still pinned, so the old
  pin can be removed.
- Routine: in a narrow window, activating a project slot also opens the Atlas & inspector
  drawer, since the inspector lives there.
