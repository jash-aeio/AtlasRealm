## Retrospective
**Went well**
- Scope held: 11 planned issues, 11 delivered, none added. In M0, 2 of 10 issues were unplanned. Holding back about 15% for review findings worked.
- Every M1 Check is proven by an end-to-end test on both the dev build and the packaged `.exe`, not just by unit tests.
- #20 (the Chromium switch guard) landed first, as planned, so the security gate wasn't left until the end.

**Didn't go well**
- Flaky tests kept costing time: the `ipc-router` "huge binary payload" test and a world-canvas test needed re-runs in most sessions. A clock-dependent test also failed CI on #37.
- Small follow-ups from security reviews are piling up in `IMPLEMENTATION_STATUS.md` (Unicode fillers in names, read caps, `WorldSummary.name`) instead of becoming issues.
- The milestone file's task states still lagged behind the merges (M1-10 stayed 🔨 after it merged).

**Change next time**
- Fix the flaky router test early in M2, so a red run means a real problem again.
- During `/plan-milestone M2`, turn each open follow-up into an issue with a deadline gate, or drop it on purpose.
- Pin the clock in any test that compares timestamps (now a review checklist item).

## Open questions
