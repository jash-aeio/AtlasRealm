# M3 — Bundled resources and permission broker

**Goal:** Bundled agent, skill and tool packages can be installed in a world, recruited into projects and checked for readiness. Every file operation goes through a trusted broker that refuses by default, asks for approval bound to the exact payload, and writes an audit record. Artifacts are real, immutable files. Existing folders can be imported through a reviewed, recoverable inspect → commit flow. (Spec §23 M3)
**Exit:** A user can assemble a project team and capabilities, and a controlled manual tool invocation can save and reopen a real artifact.
**Status:** 🔨 In progress (5/29 merged, synced 2026-11-28) · planned 2026-11-25 · **GitHub milestone:** M3 · 29 issues (21 new: #111–#131; 3 carried over: #61, #106, #108; 5 follow-ups: #135, #139, #140, #142, #145)

**Out of scope (on purpose):**
- Model calls, runs, queue and workflows: M4. Agents stay "Idle / waiting for a model". Nothing in M3 sends text to a model.
- The prompt-side re-check of stored names and goals: moved from #106 to **#132 (M4)**, a release gate before the first provider call (user choice 2026-11-25).
- Markdown link parsing and file-to-file edges: M5 ("typed derived work/file edges"). M3 only indexes artifacts and inputs as graph entities with permission filtering (user choice 2026-11-25).
- Discover tabs, downloads and community/GitHub package import: later. M3 only has bundled packages.
- Draft/Assisted/Delegated modes: they come with runs (M4). M3 offers Allow once, Deny and narrow project-scoped grants.
- Credential vault: no credentials exist yet (providers are M4).
- Editing linked originals: link mode is read-only in M3.

**Capacity:** 24 issues, a bit more than M2's 21. About 15% is held back for review findings. If M3 runs long, M3-20 (wizard UI) can slip without breaking an M3 Check, because the import commands are proven by integration tests.
